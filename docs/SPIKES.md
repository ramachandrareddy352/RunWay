| SP1 | 1 | Which `near-sdk` does `shade-attestation` allow? | `shade-attestation` 0.2.0 pins `serde_with =3.17.0`. `near-sdk` ≥ 5.30 needs `serde_with ^3.20`, so they can't coexist. `near-sdk` 5.26.1 (the version the Shade contract template pins) accepts `serde_with ^3`. | Workspace pins `near-sdk = "=5.26.1"` and `near-contract-standards = "=5.26.1"`, with `shade-attestation = "=0.2.0"` from crates.io. |
| SP1b | 1 | Which Rust compiles wasm for `near-sdk` 5.26.1? | `cargo-near` 0.23 refuses rustc > 1.86 for this SDK ("not compatible with the nearcore VM at the protocol version your contract targets"). With resolver 2, `near-sys` 0.2.14 (needs 1.93) was selected. | Wasm is built with `cargo +1.86.0 near build`. The workspace uses `resolver = "3"` with `rust-version = "1.86"` (which picks `near-sys` 0.2.9). Native tests use 1.95.0 (`rust-toolchain.toml`), because `near-workspaces` 0.24 requires it. |
| SP2 | 1 | How does sandbox time advance? | nearcore 2.14.0: each fast-forwarded block adds ≈ 1.35 s of chain time, and `fast_forward(200)` takes ≈ 10 s of wall time. An ordinary transaction takes 5–7 blocks (≈ 10–20 s of chain time). During fast-forward the **final** head stops moving until the next transaction, so chain time must be read from the optimistic head. (Earlier, on 2.6.2: ≈ 0.4 s per block.) | Rust tests fast-forward in steps until the target time. The demo jumps straight to each bucket's start time (`advanceToSec`) and fails loudly if a bucket is skipped. Sandbox buckets are 300 s, because one bucket has to fit an offer, an acceptance and a deliver + settle (≈ 80 s of chain time). |
| SP2b | 1 | Which nearcore do the sandbox harnesses run? | Rust `near-workspaces` 0.24 → `near-sandbox` 0.4.0 → nearcore 2.14.0. Its logger also ignores `NEAR_NO_LOGS`. | `scripts/lib/sandbox-binary.ts` downloads nearcore 2.14.0 (same URL as the Rust crate) and points near-workspaces at it through `NEAR_SANDBOX_BIN_PATH`/`NEAR_SANDBOX_BINARY_PATH`. Both harnesses now test one node version. `quietNearApiLogs()` silences receipt logs unless `NEAR_PRINT_LOGS=1`. |
